Open-source research kernel · pre-alpha

Remember everything. Pack only what is still true.

EviCortex is a local-first Python memory kernel for long-lived AI systems. It keeps every observation exactly as recorded, tracks which claims a newer one has replaced, and compiles a cited context capsule under a hard token budget.

The problem

Old facts look just as relevant as new ones.

Question sent to memory“Which interface theme does Ada prefer?”

01 / A PREFERENCE CHANGES

In January, Ada picks light. In April, she switches to dark.

Assistants that run for months collect facts that change. Each update is just more text in the history.

  • 2026-01-02Ada prefers the light interface theme.
  • 2026-04-18Ada switched to the dark interface theme.
02 / CHUNK RETRIEVAL PACKS BOTH

Both chunks match the question, whatever the date.

The reader model has to guess which one is still true, and the outdated chunk spends budget the current one needed.

  • stalechunk 14 · Ada prefers the light interface theme.
  • currentchunk 61 · Ada switched to the dark interface theme.
03 / EVICORTEX PACKS WHAT IS TRUE

The newer claim supersedes the older one. Nothing is deleted.

Both observations stay in the evidence ledger. Only the current fact is packed, with a stable evidence ID you can expand.

  • packeduser:ada prefers_theme = "dark" · valid from 2026-04-18
  • ledgeruser:ada prefers_theme = "light"
04 / ASK ABOUT THE PAST

Set as_of and the capsule shows what was true then.

History is a query, not a deletion. On 1 Feb 2026 the light theme was the valid claim, and that is what gets packed.

  • packeduser:ada prefers_theme = "light" · valid 2026-01-02 → 2026-04-18
  • not yet validuser:ada prefers_theme = "dark"

How it works

Three planes. One bounded capsule.

EviCortex separates the evidence it keeps from the views it uses to find that evidence. Views can be wrong or rebuilt. The evidence stays put.

01

Evidence ledger

Genome

Append-only observations with source, SHA-256 digest, namespace, and both occurrence and recording time. The lossless source of truth.

02

Memory indexes

Engram

Rebuildable claim, lexical, entity, graph, temporal and optional semantic views. A correction creates a revision instead of erasing old evidence.

03

Context compiler

Transcript

Query-time ranking, temporal filtering, conflict surfacing and packing under a strict estimated-token budget, with stable IDs you can expand later.

Interim results · cutoff 25 Oct 2026

Stale evidence stays out. Clean coverage at 4k.

0.00%

Stale-reference inclusion on knowledge updates

Across 200 knowledge-update queries at a 512-token budget, no EviCortex capsule included a superseded source. Fixed-chunk FTS and Hybrid RAG did in 100% of them.

99.27%

All gold and no forbidden IDs at 4,000 tokens

On the matched answerable cohort (n = 1,921), EviCortex packed every gold source and no forbidden one in 99.27% of queries. Both chunk baselines reached 89.59%.

iThese are source-ID retrieval proxies, not answer accuracy. No reader model was run. Each number reports which evidence IDs ended up inside the packed context.
!

Small budgets are still a weak spot

At 512 to 2,000 tokens EviCortex recovers about 70–72% of gold source IDs, while both chunk baselines recover all of them. That gap is where current research effort goes.

Methodology

How these numbers were measured.

Corpus
Authored evaluation corpus, not the official LongMemEval-S artifact
Cohort
Matched answerable cohort, n = 1,921 queries
Updates
Knowledge-update queries, n = 200, at a 512-token budget
Mode
Retrieval only. No reader model generated an answer
Budgets
512, 1,000, 2,000, 4,000 and 8,000 estimated tokens
Tokens
One token per three UTF-8 bytes, not a model tokenizer
Baselines
Fixed-chunk full-text search and a Hybrid RAG comparator
Mean source-ID recall

The average share of a query’s gold source IDs present in the packed context.

All gold and no forbidden IDs

The share of queries whose context holds every gold source and none marked forbidden.

Stale-reference inclusion

On knowledge-update queries, the share whose context includes a source a later update superseded.

Not measured here
  • Answer accuracy with a shared reader model
  • The official LongMemEval-S dataset
  • Any comparison with Mem0, Graphiti or HippoRAG 2

Quickstart

Run it on your machine.

  • Python3.12 or later
  • StorageSQLite with FTS5, included in standard CPython builds
  • Runtime depsNone beyond the standard library
  • Packageevicortex-research, imported as evicortex
  • LicenceMIT
git clone https://github.com/Varun-SV/EviCortex.git
cd EviCortex
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python examples/quickstart.py
from evicortex import ClaimInput, EviCortex

with EviCortex.open("memory.db") as memory:
    record = memory.remember(
        namespace="assistant/user-1",
        content="Ada prefers the dark interface theme.",
        source="conversation/42",
        occurred_at="2026-04-18T09:30:00Z",
        claims=[ClaimInput("user:ada", "prefers_theme", "dark")],
    )
    capsule = memory.recall(
        namespace="assistant/user-1",
        query="Which interface theme does Ada prefer?",
        budget_tokens=300,
    )
    print(capsule.to_prompt())

Roadmap

Next: small-budget recall.

The baselines fit all gold evidence into 512 tokens, so the gap comes from selection and serialization, not from the budget itself.

  2. Shipped

    Prototype A kernel

    Evidence ledger, versioned claims, valid-time recall, conflict surfacing and hard-budget packing on SQLite and FTS5.

  3. Shipped

    Extraction and embedding projections

    Audited claim-extraction boundary with exact source spans, durable semantic profiles and repair.

  4. Shipped

    Pinned semantic path

    Offline dense-encoder adapter, reranker seam and a strict LongMemEval-schema retrieval runner.

  5. In progress

    Improving small-budget recall

    Close the 512–2,000 token gap without giving back the 0% stale-reference result.

    1. Phase 1 · no modelsPer-stage miss audit and a fine budget sweep. A budget-monotone knapsack packer. A compact provenance legend. Temporal annotate-then-guard, so 0% stale holds by construction.
    2. Phase 2 · local retrievalA dense or learned-sparse channel fused with RRF, plus cross-encoder reranking for paraphrase- and distractor-heavy histories.
    3. Phase 3 · optional +LLMIngest-time proposition keys, multi-hop expansion over valid edges, and conditional query rewriting, reported as separate variants.
  6. Planned

    Official LongMemEval-S evaluation

    Byte-verified dataset, preregistered configuration, and no-memory, full-history and oracle controls.

  7. Planned

    Shared reader and answer accuracy

    Move from retrieval proxies to answers, with exact reader-tokenizer accounting and calibrated abstention.
